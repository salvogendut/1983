# RS-232C serial support — research and proposal

Status: research. This document collects the open documentation for adding an
RS-232C interface to 1983, plus a concrete proposal that mirrors how the
sibling emulators (1984, 1985) expose serial: an **Extensions > RS-232** device
backed by a host pseudo-terminal or TCP socket.

## Hardware: the MSX RS-232C interface

The MSX-standard RS-232C card is built from an **Intel 8251 USART** plus an
**Intel 8253 programmable interval timer** on a 1.8432 MHz crystal. It is
strictly **I/O-port mapped**:

| Port | Dir | Function |
|------|-----|----------|
| `80h` | R/W | 8251 USART data |
| `81h` | R/W | 8251 command / status |
| `82h` | R   | status: D7=CTS, D6=timer-2, D1=RI, D0=CD |
| `82h` | W   | interrupt mask (RXReady, TxReady, sync/break, timer) |
| `83h` | R/W | manufacturer-specific (typically RX-ready interrupt enable) |
| `84h` | R/W | 8253 counter 0 → **receive** baud clock |
| `85h` | R/W | 8253 counter 1 → **transmit** baud clock |
| `86h` | R/W | 8253 counter 2 (application) |
| `87h` | W   | 8253 mode register |

Baud rates are the 1.8432 MHz crystal divided by the 8253 scalers
(50→2304, 110→1047, 300→384, 1200→96, 9600→12, 19200→6, …).

Key details:

- **CTS is sensed via port `82h`**, not through the 8251 itself, because of a
  CTS-logic quirk in some 8251 revisions.
- DB25 pinout is the standard 8250-style modem connection (RX/TX, RTS/CTS,
  DSR, CD, DTR, RI, frame + signal ground).
- Presence is announced through `EXTBIO` (register D = `08h`, "MSX-Modem &
  RS-232C") so Extended Basic's `COMINI` and device discovery can find it.

### Two firmware generations

1. **BIOS 1.x / I/O-mapped** — the single-slot 8251+8253 card above on the
   `80h–87h` window. The classic, portable `COMINI` +
   `PRINT#`/`INPUT#`/`LINE INPUT#` COM interface.
2. **BIOS 2.0 / memory-mapped** — Sony HBI-232, ASCII MSX-Serial 232, Repro
   Factory HBI-232MKII. Multiple adapters via a memory window.

Because it exposes the well-specified `80h–87h` window and the EXTBIO `08h`
identity, the first proposal targets the **8251+8253 I/O-mapped card**.

  `MSXRS232.cc`, `RS232Tester.cc`, `RS232Net.cc`. License-compatible with
  1983 (`GPL-2.0-only`) for reuse, provided notices are kept.

## Proposal: RS-232 as an Extensions device

Mirror the 1984/1985 serial backend rather than reinventing it.

### 1. Backend layer (guest-agnostic)

New `src/rs232.{h,c}`, shaped like 1984's `usifac.c` / 1985's `serial.c`:

- `posix_openpt` → `grantpt`/`unlockpt`/`ptsname` master, open the slave once
  in raw mode (`cfmakeraw` + `CS8 | CREAD | CLOCAL`, `B9600`).
- **Stable host-side alias** symlinked to the randomised `/dev/pts/N`
  (default `/tmp/1983-rs232`) so the user can freely
  `minicom -D /tmp/1983-rs232` or `picocom /tmp/1983-rs232` before/while the
  emulator runs.
- Optional TCP backend (like 1985's `ext_serial_backend=tcp`) for remote
  attach.
- Ring-buffer RX/TX FIFOs + `rs232_poll()` drained once per frame: host→RX,
  TX→host. `rs232_rx_pop()` / `rs232_tx_push()` byte API for the USART model.

### 2. USART + timer model

- `src/serial_8251.{h,c}`: Intel **8251** USART register/clock state
  (mode/command/status, TX-ready, RX-ready, baud, the 8253 divider) —
  referenced from openMSX's `I8251` (GPL-compatible).
- `src/serial_8253.{h,c}`: the 8253 counter lanes deriving the RX/TX clocks,
  feeding the 8251, read at ports `84h–87h`.
- Wire the pair to MSX I/O ports `80h–87h` in `src/msx.c`, connecting the 8251
  RX/TX to `rs232_rx_pop`/`rs232_tx_push`.

### 3. Integration

- **Config keys** (`1983.conf`), defaulting to off:
  `rs232=off`, `rs232_backend=pty`, `rs232_pty_link=/tmp/1983-rs232`,
  `rs232_tcp_port=4400`.
- **Extensions > RS-232** item in the overlay (on/off/backend), following the
  existing `Extensions > MSX TCP/IP network` (UNAPI) row's pattern for
  on/off, surfacing the pty alias (e.g. `Status: /tmp/1983-rs232`).
- **EXTBIO device `08h`** presence so `COMINI`, `OPEN "COM0:..."`, and an MSX
  terminal program auto-detect it — the firmware-facing half of the work.

### 4. Tests and docs

- `diagnostics/test_rs232.c`: 8251 register/mode/clock, 8253 divider baud
  accuracy, `82h` CTS/RX bits, EXTBIO `08h` presence, loopback RX/TX, and the
  pty master/slave round-trip.
- Update `USAGE.md` / `README.md` links; fold the hardware notes into
  `TECHNICAL.md`.

### Acceptance check

`picocom /tmp/1983-rs232` or `minicom -D /tmp/1983-rs232` on the host alias
round-trips typed text against an MSX BASIC `OPEN "COM0:..."` + `PRINT#`
program, both directions.

The openMSX pieces (RS232Net, I8251) are already GPL-2.0 — reuse keeps the
project license consistent and gives a battle-tested core to port rather than
hand-rolling the 8251.
